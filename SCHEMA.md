# Схема БД каталога WoSB — v0.8

`catalog.json` этого репозитория — **единственный источник правды** о
каталоге игры: предметы, рецепты, мануфактуры и их уровни.

Роли сторон:

- **Приложение** (WoSB Assistant, Android) хранит встроенную копию
  (`assets/catalog/catalog.json`) для первого запуска и оффлайна;
  обновления получает из этого репозитория (открытое чтение без токена).
- **Админ** правит БД в приложении (скрытая админка) и коммитит сюда
  через GitHub Contents API (fine-grained PAT, `contents:write`, только
  этот репозиторий, хранится в Keystore телефона).
- **CI** этого репозитория при каждом push валидирует файл; приложение
  предлагает обновление только по «зелёным» коммитам.

Формат — формат каталога приложения (`CatalogFile.kt` +
`CatalogParser`), сейчас версия 2: редактор, CI и приложение
переиспользуют одни и те же правила валидации.

**История:** v0.1 — черновик; v0.2 — решения владельца зафиксированы:
группы переезжают в данные (§2), введён протокол переименования
`renames.json` (§6), разбиение файла / число уровней / политика новых
полей — подтверждены (§10); v0.3 — крафт-время измеряется в **единицах**
(ключ переименован в `craftTime`, формат поднят до 2, §4), у мануфактур
флаг доступности «опасных вод» (§5); v0.4 — группы получают **kind**
(resources/tools/ships, §2), у ресурсов флаги «материал для
орудий/кораблей» (§3), правила крафт-юнитов: без веса и времени,
у кораблей выход 1 (§4), группа 1 переименована «Предметы» →
«Ресурсы»; v0.5 (wosb-android-79) — kind **ammunition** «Боеприпасы»
(§2, §3, §4) и у ресурсов флаг «Материал для боеприпасов» (§3);
формат остаётся 2 — новые ключи опциональны (§1); v0.6
(wosb-android-86) — у кораблей признак **«Ранг»** (обязательный,
римские цифры I–VII, §3), в каталоге калькулятора фильтр по рангу
(ряд из 7 кнопок, множественный выбор); v0.7 (wosb-android-87) —
у орудий признак **«Категория»** (опциональный:
Легкие/Средние/Тяжелые/Мортиры, §3), в каталоге калькулятора фильтр
по категории (ряд из 4 кнопок, множественный выбор); v0.8
(wosb-android-118) — у кораблей блок **характеристик `ship`**
(опциональный, §3): класс, фракция, прочность, скорость,
манёвренность, броня, трюм, экипаж, габариты корпуса, водоизмещение,
бортовые орудия (калибр + корма/борт/нос), фальконеты, целостность
(потоплений до капремонта; отсутствие — бесконечная, у части
кораблей рангов VI–VII), особые свойства (сырая строка). Заполнено
из фан-гайда wosbcraft.com (снято 28.10.2026; все корабли
«Coming Soon» — значения ориентировочные); в приложении ляжет в
основу экрана сравнения/сортировки кораблей (первичный ключ — ранг).

## 1. Корневая структура файла

| Поле | Тип | Значение |
|---|---|---|
| `app` | string | Метка `wosb-catalog`; файлы с другой меткой отклоняются |
| `formatVersion` | int | Версия формата, сейчас `2`. Формат 2 отличается от 1 переименованием ключа крафт-времени (`craftTimeHours` → `craftTime`, §4); файлы формата 1 репозиторий отклоняет. Файл с большей версией старое приложение не примет («обновите приложение») |
| `exportedAt` | long (мс) | Метка времени последнего изменения; редактор обновляет при каждом коммите |
| `source` | string | Происхождение версии: `bot-db` (исходный экспорт), `editor` (правка из приложения), … — свободная метка |
| `items` | array | Предметы. Порядок массива не значим: показ на экранах определяют `group`, `sortOrder`, `name` |
| `groups` | array | **С v0.2**: группы каталога `{id, emoji, title}` (§2). Порядок секции = порядок блоков на экранах. Отсутствует только в легаси-файлах — приложение использует встроенные 1/2/3 |

Рядом с `catalog.json` живёт **`renames.json`** — append-only журнал
переименований (§6).

Неизвестные поля игнорируются (`ignoreUnknownKeys`) — прямая
совместимость: новые поля можно добавлять заранее, старые версии
приложения их молча пропустят.

## 2. Группы (`groups`) — данные, назначает админ

Решение владельца (v0.2): группа назначается админом предмету, список
групп редактируем — секция живёт в JSON, а не в коде.

| Поле | Тип | Правило |
|---|---|---|
| `id` | int | Положительный, уникальный. На него ссылается `item.group` |
| `emoji` | string | Непустой; показывается в заголовке блока |
| `title` | string | Непустое название («Ресурсы», «Орудия», «Корабли») |
| `kind` | string | **С v0.4**: семантика группы — `resources` (обычные предметы), `tools` (орудия), `ships` (корабли) или **с v0.5** `ammunition` (боеприпасы). Отсутствие ключа (легаси) трактуется как `resources`. Правила юнит-групп и боеприпасов — §3/§4; редактор приложения подстраивает форму предмета под kind; смета калькулятора строит сводку по kind цели (wosb-android-79) |

- Порядок блоков на экране = порядок секции (не сортируется).
- Склейка «emoji + неразрывный пробел + title» — забота приложения
  (правило неразрывности эмодзи, wosb-android-32).
- Seed-данные: `1 📦 Ресурсы (resources)`, `2 💣 Орудия (tools)`,
  `3 ⛵ Корабли (ships)`, **с v0.5** `4 🧨 Боеприпасы (ammunition)`. С v0.4
  группа 1 называется «Ресурсы» (решение владельца, wosb-android-43),
  группа 4 добавлена по команде владельца (wosb-android-79).
- В коде приложения остаётся встроенный фолбэк 1/2/3/4 для файлов без
  секции (легаси) и для случаев «группа не найдена».

## 3. Предмет (`items[i]`)

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `name` | string | — | **Ключ предмета.** Уникальное, непустое. По нему ссылаются рецепты, расходники мануфактур, цены и дефолты пользователя. Переименование — только операцией редактора (§6) |
| `group` | int | 1 | **Назначается админом**: id группы из секции `groups` (§2) |
| `weight` | int | 0 | Вес единицы (итоговый вес сметы), `≥ 0` |
| `sortOrder` | int | 0 | Порядок в группе; при равных значениях — по алфавиту (`sortOrder ASC, name ASC`) |
| `isSea` | bool | false | Источник «🌊 Море» |
| `isManufactory` | bool | false | Источник «🏭 Мануфактура» (требует конфиг `manufactory`) |
| `isCraft` | bool | false | Источник «Крафт» — **обязан** иметь `recipe` |
| `isMarket` | bool | false | Источник «Рынок» (закупочная цена) |
| `isCurrency` | bool | false | Источник «Валюта» («Золото») |
| `isToolMaterial` | bool | false | **С v0.4**: материал для рецептов ОРУДИЙ — при настройке рецепта предмета группы с kind `tools` в выборе материалов предлагаются только предметы с этим флагом (§4) |
| `isShipMaterial` | bool | false | **С v0.4**: материал для рецептов КОРАБЛЕЙ — аналогично для групп с kind `ships` |
| `isAmmoMaterial` | bool | false | **С v0.5** (wosb-android-79): материал для рецептов БОЕПРИПАСОВ — аналогично для групп с kind `ammunition` |
| `rank` | string | — | **С v0.6** (wosb-android-86): **Ранг корабля** — только в группах с kind `ships`; значение — римская цифра `I`…`VII`. У кораблей ОБЯЗАТЕЛЕН (репозиторий строг; парсер приложения терпит отсутствие — легаси-каталоги без рангов валидны). Заполняется владельцем из редактора приложения (форма корабля — ряд кнопок I–VII); в каталоге калькулятора по рангу работает фильтр блока «Корабли» |
| `category` | string | — | **С v0.7** (wosb-android-87): **Категория орудия** — только в группах с kind `tools`; значение — `Легкие`/`Средние`/`Тяжелые`/`Мортиры`. ОПЦИОНАЛЬНА (в названиях орудий не закодирована — проставит владелец из админки; предзаполнены только «Мортиры» — 6 орудий «Мортира …»). Репозиторий строг к значению и носителю: незнакомая категория/вне `tools` — ошибка; парсер приложения отличается только терпимостью к отсутствию. В каталоге калькулятора по категории работает фильтр блока «Орудия» (ряд из 4 кнопок, множественный выбор) |
| `recipe` | object \| null | null | Рецепт крафта (§4) |
| `manufactory` | object \| null | null | Конфиг мануфактуры (§5) |
| `ship` | object \| null | null | **С v0.8** (wosb-android-118): **Характеристики корабля** — только в группах с kind `ships`; ОПЦИОНАЛЕН (парсер приложения терпит отсутствие). Поля: `class` — `Боевой`/`Быстроходный`/`Тяжёлый`/`Транспортный`/`Осадный`/`Императорский`; `faction` — `Премиум`/`Антилия`/`Эспаньол`/`Кай и Северия`/`Империя`; `durability` (прочность), `maneuverability`, `cargo` (трюм), `crew` (экипаж), `hullLength`/`hullWidth` (корпус Д×Ш), `displacementTons`, `gunsStern`/`gunsBroadside`/`gunsBow` (орудия корма/борт/нос), `falconets` — целые; `speedKnots` (уз), `armor` — числа. `gunCaliber` — `Легкие`/`Средние`/`Тяжелые` (словарь категорий орудий v0.7 без мортир): обязателен при сумме орудий > 0, запрещён при 0 (безоружные Balloon, Axel Thorsen). `integrity` — целое ≥ 1, потоплений до капремонта; отсутствие = бесконечная (все VII и часть VI). `specials` — непустая строка, сырой список особых свойств источника (разделитель «;»). Репозиторий строг к носителю/значениям/неизвестным полям |

Порядок кнопок источников в приложении фиксирован: море → мануфактура
→ крафт → рынок → валюта.

**Правила крафт-юнитов (v0.4).** Предмет группы с kind `tools` или
`ships` («орудия»/«корабли») — крафт-юнит: создаётся ТОЛЬКО крафтом
(`isCraft: true` + `recipe`), веса и крафт-времени у него нет
(`weight: 0`, `craftTime: 0`), другие источники и `manufactory`
запрещены. Форма редактора соответствующие поля не показывает и
фиксирует значения при сохранении; валидатор (CI и приложение)
отклоняет нарушения. У предметов групп `tools`/`ships` флаги
`isToolMaterial`/`isShipMaterial` смысла не имеют (юниты — не
материалы).

**Правила боеприпасов (v0.5, wosb-android-79).** Предмет группы с kind
`ammunition` — тоже только крафт (`isCraft: true` + `recipe`), без
`manufactory` и других источников. В ОТЛИЧИЕ от юнитов вес и
крафт-время ЗАДАЮТСЯ (`weight ≥ 0`, `craftTime ≥ 0`): вес партии
показывается на смете калькулятора рядом с себестоимостью партии, а
плашка «Вес» внизу сметы не рисуется; у боеприпасов также скрыты
безубыточность и кнопка налога биржи (решение владельца). Выход
задаёт админ — батчевый. Материалы требуют флаг `isAmmoMaterial`.

**Признак «Ранг» (v0.6, wosb-android-86).** У предмета группы с kind
`ships` ключ `rank` обязателен — одна римская цифра из `I`, `II`,
`III`, `IV`, `V`, `VI`, `VII` (7 рангов, решение владельца).
Вне кораблей ранг запрещён. Репозиторий отклоняет корабль без ранга,
с незнакомым значением или с рангом вне `ships`; парсер приложения
при загрузке терпит только ОТСУТСТВИЕ ранга (легаси) — неверное
ЗНАЧЕНИЕ или ранг у не-корабля приложение тоже отклоняет. Фильтр
по рангу в каталоге калькулятора: развёрнутый блок «Корабли» содержит
ряд из 7 кнопок I–VII (множественный выбор): пустой выбор — все
корабли, непустой — только корабли выбранных рангов (корабли без
ранга в легаси-каталоге скрываются).

**Признак «Категория» (v0.7, wosb-android-87).** У предмета группы с
kind `tools` ключ `category` — одна из `Легкие`, `Средние`, `Тяжелые`,
`Мортиры` (решение владельца). Вне орудий категория запрещена.
В ОТЛИЧИЕ от ранга, категория ОПЦИОНАЛЬНА: в названиях орудий она не
закодирована — значения проставит владелец из админки (форма орудия —
ряд 4 кнопок, одиночный выбор); предзаполнены только «Мортиры»
(6 орудий с именем «Мортира …»). Репозиторий отклоняет незнакомое
значение или категорию вне `tools`; парсер приложения отличается
только терпимостью к отсутствию. Фильтр по категории в каталоге
калькулятора: развёрнутый блок «Орудия» содержит ряд из 4 кнопок
(множественный выбор): пустой выбор — все орудия, непустой — только
орудия выбранных категорий (орудия без категории скрываются при
активном фильтре).

## 4. Рецепт (`recipe`)

| Поле | Тип | Правило |
|---|---|---|
| `outputQuantity` | double | Выход за один крафт, `> 0`. **С v0.4**: у предметов группы `ships` — всегда `1` (корабль собирается по одному; у орудий выход задаёт админ — у снарядов он батчевый). **С v0.5**: у боеприпасов выход тоже батчевый на усмотрение админа |
| `craftTime` | double | «Крафт-время» в **единицах**, `≥ 0`; у части рецептов `0`. **С v0.4**: у предметов групп `tools`/`ships` — всегда `0` (у крафт-юнитов крафт-времени нет). **С v0.5**: у боеприпасов время задаётся (плашка «Крафт-время» на смете у них остаётся) |
| `materials` | array | Материалы: `{name: ссылка на предмет, quantity: > 0}`. Каждая ссылка обязана существовать в каталоге |

Решение владельца (v0.3): крафт-время — **абстрактный расходник
крафта, измеряется в единицах**: со временем как таковым не связано и
в часах не измеряется (приложение и так показывает его как «N ед.»).
В смете собственное крафт-время строки = `craftTime × количество
крафтов`, по цепочке суммируется, как раньше.

Историческое имя ключа — `craftTimeHours` (формат 1): суффикс «Hours»
вводил в заблуждение насчёт единицы. В формате 2 ключ переименован в
`craftTime`, версия формата поднята до `2`; файлы формата 1
репозиторий отклоняет (§1, §8).

## 5. Мануфактура (`manufactory`)

| Поле | Тип | Правило |
|---|---|---|
| `displayName` | string | Показываемое имя («Лесопилка», «Производство рома»); пустое → «Мануфактура». В расчёте не участвует — только показ |
| `canUsePrisoners` | bool | Доступен ресурс «Пленные». Расход пленных всегда ровно **2 шт./час** — не множится ни уровнем, ни опасными водами |
| `availableInDangerousWaters` | bool | **Доступна в «опасных водах»** (решение владельца v0.3). Чекбокс «опасные воды» (×1.25) в расчёте предлагается только мануфактурам с этим флагом — по образцу `canUsePrisoners`, который так же разрешает чекбокс «пленные». В репозитории ключ обязателен; парсер приложения трактует отсутствие как `false` |
| `consumables` | array of string | Ресурсы, которые мануфактура может расходовать; ссылки обязаны существовать |
| `levels` | array | Таблица уровней: **либо пусто** (настройка свободным вводом чисел), **либо ровно 4 уровня** (решение владельца v0.2). Уровень: `{speedPerHour: > 0, consumesPerHour: {имя ресурса: ≥ 0}}`, все ресурсы существуют |

Множители в JSON не хранятся — они часть кода приложения:
«опасные воды» ×1.25 к скорости и расходу, «пленные» ×2; множители
перемножаются (база × 1.25 × 2 = ×2.5). В БД — только базовые числа
уровней. Оба чекбокса в расчёте видны только там, где их разрешают
флаги БД: «опасные воды» — при `availableInDangerousWaters`,
«пленные» — при `canUsePrisoners`.

## 6. Переименование предмета — протокол `renames.json`

Имя предмета — ключ, на который завязаны рецепты, расходники и
пользовательские данные (цены, дефолты, мануфактуры, планы). Поэтому
**переименование — операция редактора, а не правка одного поля**:

1. Админ в редакторе переименовывает предмет («Ткань» → «Полотно»).
2. Редактор пишет **пару Contents-коммитов** — сначала `catalog.json`,
   затем `renames.json` (Contents API коммитит один файл за раз, а
   PATCH из Git Data API недоступен в HTTP-стеке приложения):
   - `catalog.json` — новое имя + **все** ссылки (материалы рецептов
     других предметов, `consumables`, ключи `consumesPerHour`);
   - `renames.json` — дозапись `{from, to, at}` (`at` — время, мс)
     **поверх свежей версии журнала** (чужие записи сохраняются).
   Каждый промежуточный sha самосогласован: устройства пинуют оба
   файла к **одному** sha коммита (`raw.githubusercontent.com/<sha>/…`),
   журнал применяют целиком и идемпотентно — «окна рассинхрона» нет;
   сбой на втором коммите само-лечится повтором (уже уехавший каталог
   не коммитится второй раз).
3. `renames.json` — **append-only журнал**: записи никогда не удаляются
   и не редактируются; цепочки переименований (А→Б, Б→В) применяются
   устройствами строго по порядку. Правило имён: имя из колонки
   «from» нельзя выдать **другому** предмету (ни переименованием, ни
   созданием) — иначе повторное применение журнала захватило бы данные
   нового предмета старой записью. Исключение — **возврат предмету его
   собственного прежнего имени** (обратный проход по журналу строит
   цепочку имён предмета; редактор проверяет её, wosb-android-39):
   журнал применяется устройствами целиком и по порядку, поэтому данные
   предмета проходят всю его цепочку и сходятся к финальному имени —
   и возврат А→Б→А, и возврат через несколько шагов, и новое
   переименование после возврата остаются идемпотентными. Освободившееся
   при возврате имя («Б») само становится «from» — другим предметам оно
   отныне недоступно.
4. Устройства при «Обновить БД» применяют журнал к локальным
   пользовательским данным — 4 UPDATE по `itemName` (цены, дефолты,
   мануфактуры, планы). Движок расчёта и Room-схема не меняются.
5. Переименование руками в GitHub (мимо редактора) журнал не
   заполняет: валидатор поймает битые ссылки в `catalog.json`, но
   пользовательские данные останутся на старом имени. Правило:
   **переименование — только через редактор**.

Альтернатива — стабильные `id` вместо имён — рассмотрена и отклонена
на v0.2: требует рефакторинга движка (`CalcSession` на именах),
миграции Room-таблиц пользователя и кодека бэкапа. Если переименования
станут частыми — вернуться к вопросу отдельной фазой.

## 7. Служебные соглашения

- **«Пленные»** — обычный предмет каталога с зарезервированным именем.
  Если у мануфактуры `canUsePrisoners: true`, предмет «Пленные» должен
  быть в каталоге (CI предупреждает, если отсутствует).
- **«Золото»** — предмет-валюта (`isCurrency: true`).

## 8. Правила валидации (CI + приложение)

Валидатор `tools/validate_catalog.py` повторяет `CatalogParser`
приложения и добавляет проверки, которых у приложения нет на этапе
загрузки. Полный список:

1. `app` = `wosb-catalog`; `formatVersion` = 2 (меньше — устаревший
   формат 1, больше — «обновите приложение»).
2. **groups**: id — положительные уникальные целые; emoji и title
   непустые; **группа каждого предмета существует** (если секция есть;
   без секции — легаси-режим, предупреждение о неизвестной группе).
   **С v0.4**: `kind` — один из `resources`/`tools`/`ships`
   (отсутствие — `resources`). **С v0.5**: добавлен `ammunition`.
3. Названия предметов непустые и уникальные; вес `≥ 0`.
4. `isCraft: true` ⇒ есть рецепт.
5. Рецепт: выход `> 0`; крафт-время `craftTime` — число `≥ 0`
   (устаревший ключ `craftTimeHours` — ошибка); каждый материал
   существует; количество материала `> 0`.
6. Мануфактура: расходники существуют; уровней либо 0, либо ровно 4;
   скорость каждого уровня `> 0`; расход `≥ 0`; ресурсы уровней
   существуют; флаг `availableInDangerousWaters` обязателен (булев).
7. **Крафт-юниты (с v0.4)**: предмет группы с kind `tools`/`ships` —
   только крафт (без чужих источников), `weight: 0`, `craftTime: 0`,
   без мануфактуры; у `ships` выход рецепта всегда `1`.
   **Боеприпасы (с v0.5)**: предмет группы с kind `ammunition` — тоже
   только крафт, без мануфактуры и чужих источников, но вес и
   крафт-время задаются (§3).
8. **Флаги материалов (с v0.4)**: каждый материал рецепта предмета
   группы `tools` обязан иметь `isToolMaterial: true`, группы `ships` —
   `isShipMaterial: true`, **с v0.5** группы `ammunition` —
   `isAmmoMaterial: true` (так держится фильтр выбора в редакторе).
9. **Циклы в графе рецептов запрещены** (DFS по рёбрам «предмет с
   рецептом → материал с рецептом»). В приложении та же проверка
   выполняется при расчёте (`CalcSession`, сообщение
   «Обнаружен цикл в рецептах: A → B → A»); CI проверяет заранее.
10. **renames.json**: метка приложения; каждая запись — непустые
    `from`/`to`, `from` ≠ `to`, корректная метка времени; предупреждение,
    если `to` нет в текущем каталоге (переименован снова).
11. **Ранг корабля (с v0.6, wosb-android-86)**: ключ `rank` — только
    в группах kind `ships` и только значением из `I`…`VII`; у кораблей
    обязателен. Незнакомое значение, ранг вне `ships` или корабль без
    ранга — ошибка. Парсер приложения при загрузке отличается ТОЛЬКО
    терпимостью к отсутствию ранга (легаси-каталоги).
12. **Категория орудия (с v0.7, wosb-android-87)**: ключ `category` —
    только в группах kind `tools` и только значением из
    `Легкие`/`Средние`/`Тяжелые`/`Мортиры`; ОПЦИОНАЛЬНА. Незнакомое
    значение или категория вне `tools` — ошибка. Парсер приложения
    отличается только терпимостью к отсутствию.

Предупреждения (не валят CI): рецепт без флага `isCraft`; неизвестная
группа в легаси-режиме; `canUsePrisoners` без предмета «Пленные».

Текущее состояние данных (v0.7): **126 предметов** (36 ресурсов /
22 орудия / 63 корабля / 5 боеприпасов), 103 с рецептом, 9 мануфактур —
все с таблицей из 4 уровней, 4 группы (`resources`/`tools`/`ships`/
`ammunition`). Ранги (v0.6) проставлены всем 63 кораблям — из названий
владельца («Poltava (III)» → `III`): I×6, II×9, III×12, IV×11, V×11,
VI×10, VII×4. Категории (v0.7) предзаполнены у 6 мортир («Мортира …» →
`Мортиры`); у остальных 16 орудий категорию проставит владелец
(опциональна). Флаг `availableInDangerousWaters` у мануфактур задаёт
владелец (у «Боевой марки» выключен). 18 ресурсов помечены флагами
материалов орудий/кораблей (§3; у 3 из них оба флага); крафт-время
снарядов нормализовано в 0 (wosb-android-43).
Ключ `isAmmoMaterial` у всех предметов — `false` (wosb-android-79):
владелец отметит им материалы будущих рецептов боеприпасов.

## 9. Жизненный цикл правки БД

1. **Сессия правок** в админке приложения (предметы, рецепты,
   мануфактуры, группы) → «Записать в GitHub».
2. Приложение валидирует итог локально (тот же набор правил),
   берёт текущий `sha` файла (`GET /repos/…/contents/catalog.json`)
   и кладёт новую версию одним коммитом (`PUT`) с осмысленным
   сообщением; при переименовании — вместе с записью в `renames.json`.
3. Конфликт (`409/422`, файл уже изменён): диалог
   «Перечитать из GitHub (правка сохранится черновиком) / Перезаписать».
4. **CI** гоняет валидатор; красный коммит в обновления не попадает.
5. **Пользователи**: приложение сверяет последний коммит `main`
   (открытое API; статус CI читается без токена) и предлагает
   «Обновить БД» — загрузка `catalog.json` + `renames.json`,
   применение переименований к локальным данным (§6), локальная
   валидация, применение. Встроенный файл остаётся оффлайн-фолбэком.
   Git-история репозитория = полный журнал изменений БД.

## 10. Решения владельца (v0.2, зафиксировано)

| # | Вопрос v0.1 | Решение |
|---|---|---|
| 1 | Ключ предмета: имя или id | **Имя** + протокол переименования `renames.json` (§6); id — возможная будущая фаза, если переименования станут частыми |
| 2 | Один файл или разбиение | **Один** `catalog.json` |
| 3 | Число уровней мануфактуры | **Ровно 4** (жёсткое правило) |
| 4 | Группы | **Группы — данные**: секция `groups` (§2), группа назначается админом |
| 5 | Новые поля формата | Не добавлять без реальной потребности; `ignoreUnknownKeys` позволяет расширять позже |
| 6 | Единица крафт-времени (§4) | **Единицы, не часы** — абстрактный расходник; ключ переименован в `craftTime`, формат поднят до 2 |
| 7 | Мануфактуры в «опасных водах» (§5) | **Флаг `availableInDangerousWaters`**: чекбокс ×1.25 только у отмеченных (аналог `canUsePrisoners`); стартово у всех `true`, исключения вносит владелец |

## 11. Тексты интерфейса — `texts.json` (wosb-android-75)

Рядом с каталогом лежит `texts.json` — переопределения текстовых
блоков интерфейса приложения (заголовки и подсказки экранов, тексты
разделов «Настроек» и диалогов очистки). Принцип — тот же, что у
каталога: правится из скрытой админки приложения («Тексты
интерфейса»), коммитится Contents API (SHA-протокол, §8), гейтится
CI (§8), доезжает до устройств через «Обновить БД» (§9) тем же
пином sha, что и `catalog.json`.

Ключевые отличия от каталога:

- **Реестр блоков живёт в приложении** (AppTexts.kt): стабильный
  идентификатор (`calc.hint`, `settings.reset.hint.all`, …), подпись
  для админки и встроенный дефолт. Файл хранит ТОЛЬКО отличия от
  дефолтов — отсутствующий в файле блок показывается по дефолту.
- **Прямая совместимость**: незнакомые идентификаторы (файл написал
  редактор более новой версии) — легальны; валидируется только
  структура (метка `app: "wosb-texts"`, `formatVersion: 1`,
  непустые идентификаторы и значения). Снятие переопределения —
  удаление ключа (устройство возвращается к дефолту, в том числе
  будущему после обновления приложения).
- **Без журнала переименований**: блок — одно значение; протокол
  renames.json не нужен. Черновики правок на диск не пишутся
  (правка короткая).

Формат файла:

```json
{
  "app": "wosb-texts",
  "formatVersion": 1,
  "exportedAt": 1792919592475,
  "source": "app-defaults",
  "texts": {
    "calc.hint": "Новая подсказка экрана калькулятора"
  }
}
```

Пустая секция `texts` — легальное начальное состояние (все блоки по
дефолтам приложения). CI проверяет структуру
(`tools/validate_catalog.py catalog.json renames.json texts.json`);
коммиты только по texts.json тоже триггерят проверку (paths-фильтр
воркфлоу включает `texts.json`) — иначе гейт «Обновить БД» не
увидел бы зелёной проверки и тексты никогда не доезжали бы до
устройств.
